- **Builds and completion write Store format 0.3.0, a new series that older packages
  refuse (issue #467, ADR 0105).** Not released until #468–#472 land on epic #450's
  branch. A 0.3.0 release indexes its ALIDs with a variable-length sidecar
  (`variant_alid_utf8.npy`, `variant_alid_offsets.npy`, `variant_alid_keys.npy`,
  `variant_alid_order.npy`). The sidecar holds every ALID, however long. The fixed-width
  `variant_alid_bytes.npy`/`variant_alid_rows.npy` pair, which is no longer written, left
  out each ALID over 32 bytes. Those resolved only by scanning the Variant Table with
  pysam: 115,043 such ALIDs on OGS-00010, 2,026 on OGS-00024. On 0.3.0, `lookup` and
  `phewas` by such an ALID return its row without loading pysam. A package without the
  0.3 series refuses a 0.3.0 release by name (`… declares format_version='0.3.0', a release
  series this build does not implement`). This package still reads 0.1.0 and every 0.2
  release.
- **`ogdb rewrite-release SOURCE DESTINATION` derives a new 0.3.0 release from a 0.2.3
  one (spec §21.4).** It never writes its source and refuses a destination that exists.
  It runs named steps on a staged copy; #468–#472 each add one. Before it publishes, it
  asks the source and the copy the same fixed set of questions and refuses on any
  difference, then validates the copy. The questions include the release's longest ALIDs
  and ALIDs at 23, 24, 25, 32 and 33 bytes, and the step refuses unless every ALID resolves
  to its own row. A release before 0.2.3 is refused: it lacks 0.2.3's reference-first
  indels and SE count, which no rewrite can add, so it is rebuilt. Hosted Stores are not
  rewritten: they are rebuilt from source at 0.3.0 (opengwas/opengwasdb-stores#498). The
  rewrite proves each format step on fixture and small releases.
- **New validation rule `variant_table.alid_sidecar`.** It checks a 0.3.0 release's
  sidecar against its Variant Table. `envelope.required` and `envelope.closed` now follow
  the release's version: the sidecar from 0.3.0, the fixed-width pair before it.
- **The query-result digests are production code (`opengwasdb.store.query_digests`).** The
  rewrite's proof and the store-reader golden test share them, and the store-comparison
  benchmark takes `digest_array` and `result_digests` from there.
- `docs/store-format-compatibility.md` has the 0.3.0 row. Both repositories' docs change:
  opengwasdb-stores' release manifests and walkthrough name the envelope's files.

- **A two-pass build compares the names a site's spellings carry, as a single-pass build does (issue #379, ADR 0066 clarified).** Where sources spell one site in different case (`a`/`g` and `A`/`G`) and name it with different rsids, a `build-hybrid --reference-panel` or two-pass `build-dense-vcf` build kept the first source's name, so a single-pass build of the same sources named the variant differently and the two-pass name depended on which source the manifest listed first. Now every rsid harvest applies one test: `build-hybrid` refuses such a key under `--on-rsid-conflict refuse`, the default, naming the key and both names, and under `drop` stores every variant it reaches with no rsid. A `--reference-panel` build now accepts `drop`, and its JSON summary reports `rsid_conflicts` counts where it reported `null`; only a reference that names its own variants still reports `null`. `build-dense-vcf` has no option and refuses, in either mode. `extract-variant-reference` refuses such a key too, so an artifact a build uses as given never carries a disputed name. A refusal names the mode that met it, such as `Hybrid two-pass build:`. `build-dense` and `build-ragged-ssf` are unchanged: the rows they read carry no source spelling to compare. No published Store's names change, and none would refuse to rebuild: routing the recorded sources of OGS-00003, OGS-00004 and OGS-00008 finds 0 disputed keys, and the other two-pass Stores (OGS-00009, OGS-00012 to OGS-00017), whose ALIDs still carry their sources' case, hold no lower-case allele.

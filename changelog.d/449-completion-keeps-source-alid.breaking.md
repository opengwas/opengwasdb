- **Reference Completion keeps each observed row's `source_alid`, and the validator refuses a lifted release with none (issue #449).** Dense and Ragged completion rewrote the Store Variant Table without the pre-liftover ALID the build recorded, so a completed release lost which source variant any row came from (OGS-00009: `.` on all 11,191,070 rows) and nothing failed. Observed rows now keep their source's `source_alid`; rows added from the panel stay `.`, and a row the build left blank stays blank. The new rule `variant_table.source_alid` fails a release whose manifest records a liftover (`provenance.chain_file`, or a `provenance.lift` that lifted a variant) and whose table holds no `source_alid` at all, on every `format_version`.

  Ragged builds (`build-ragged-ssf`, `build-ragged-besd`) now write `source_alid` too: the pre-lift ALID of a lifted row, the ALID itself for an unlifted one, and `.` where two origins reach one variant (#85).
  **A hosted release built before this fails the new rule until it is rebuilt** (opengwas/opengwasdb-stores#498): every completed 0.2 Dense release that lifted, and every lifted Ragged release, holds no `source_alid`.

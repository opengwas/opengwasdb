- **Resolution now refuses an Analysis whose effect contradicts its own source's p-value (issue #345, ADR 0069).** `resolve-analyses` compares the z-score a build would store (`beta / se`) with the p-value the source reports, on a bounded deterministic sample of the rows the build would admit, and fails the Analysis as a controlled failure when the median |log10 p implied − log10 p reported| exceeds 1.0 orders of magnitude. It catches a `beta` column holding odds ratios and an `odds_ratio` column holding log-odds, which resolved without complaint before. On the 4,783 OGS-00011 sources 4 are refused (0.1%): `GCST002047` (median |Δ| 1,732) and `GCST004461` (247), the two named cases, and `GCST90503316` (813) and `GCST90165257` (12.9), found by the check; the largest clean source is 0.346. Rows whose standard error was derived from the p-value are not compared. Every record gains `diagnostics.effect_consistency` (the measurement, or a recorded `skip_reason`: `no_source_p_value`, which includes GWAS-VCF and BESD for now, `all_se_from_p_value` or `too_few_rows`) and `resolution_config.effect_consistency` (the threshold and minimum row count, overridable by a caller), so records resolved earlier are recomputed by `--resume`. The built-in `finngen-r13` Column Map now maps `pval`, so FinnGen Analyses are checked too (40 clean endpoints: max median |Δ| 5.5e-7); its checksum is bound into every record read through it, so FinnGen records are recomputed by `--resume`, and, as for any Column Map declaring `p_value`, a row with an unusable `sebeta` and a usable `pval` now gets a standard error from the p-value, where the dedicated FinnGen reader drops it (ADR 0055 amended; 0 such rows in 40 R13 endpoints, 146M rows scanned). A sample bound (`evidence_sample`) below the check's minimum row count (50) is refused with a `ValueError`.

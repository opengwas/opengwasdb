- **Every layout's queries decide whether an association is present by one rule, and read through one module (issue #351, ADR 0068).** An association is present exactly when neither its Z nor its SE carries its plane's missing marker (spec §15); an infinite SE is a value. Dense `analysis()`, `phewas()`, `range_phewas()` and `lookup()` used to drop a cell whose SE was stored `+inf` (an SE above `float16`'s range, #338), and Ragged, Hybrid Overflow and Dense `top_hits()` labelled it `missing`; every layout now returns it `observed` (or `imputed`) with `se = inf`. On the published Store Releases this touches eight cells, all in OGS-00011: four Dense Component cells that now appear and four Overflow cells that change from `missing` to `observed`. A cell spec §15 forbids — one marker without the other, an imputed flag other than 0 or 1, or a flag on a missing cell — now raises `InvalidAssociations` naming the component and the first cells, where Dense dropped it and Ragged read it as missing; no published release holds one. Query methods return an `opengwasdb.associations.Associations` record instead of a `dict`: it reads as the same mapping, with the same keys and dtypes, but cannot be mutated and is not a `dict` instance. Dense `lookup()` is now Analysis-major, as Ragged's already was. ADR 0033 §7 and §8 are superseded.

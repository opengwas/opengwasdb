- **`overview.html` is gathered from a Store Release and then rendered from that value, so the renderer takes data rather than a path (issue #57, ADR 0032).** `opengwasdb/overview.py` replaces `opengwasdb/layouts/dense/overview.py`: `gather_store_overview()` reads the manifest summary, the Guide's directory scan, the Rho summary (including its histogram bins and hierarchical clustering) and the Indexed Variant Subsets into a `StoreOverview` value, and `render_overview_html()` turns that value into HTML with no I/O at all. The page a given Store Release renders is byte-identical to before, and `ogdb regenerate-overview` and the builders call the same `write_overview_html()` entry point as before.

  The label an Analysis is displayed under now has one implementation, `opengwasdb.model.analyses.analysis_label()`, used by the Rho tab (issue #57); `analyses_table()` still hands the stored `analysis_label` column through unchanged, blank included, because a blank cell says the release supplied no label.

- **`validate` runs named Validation Rules, and its result says which rule found what (issue #55, ADR 0074).** `validate_store()` returns a `ValidationResult` whose `findings` each carry the rule's stable name, a severity and the target it judged. `failed()` gives the names of the rules that reported an error, and `of(name)` a rule's findings. `skipped` gives the rules that did not run, and why: the rules they depend on that failed or were skipped, or the rule's own reason, such as "no frequencies" for a frequency range check on a component holding none. `validate_store(path, rules={...})` runs the named rules and the rules they depend on, and refuses a name no rule has before anything is read. Spec §20.0 lists every rule, in the order it runs, and the test suite holds the list to the registry. A check no longer stops because some other, unrelated check failed earlier, so a release with two independent defects reports both. The rules that judge association values share one streamed read: each plane is read once per component, not up to six times. `errors`, `warnings` and `ok` read as before, and `validate --format json` and the text output are unchanged: on every published Store Release the output is byte-identical, except the three 0.1.0 releases #380 makes pass.

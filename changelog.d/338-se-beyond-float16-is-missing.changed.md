- **An SE above float16's maximum (65,504) is stored as missing, and `format_version` moves from 0.2.0 to 0.2.1 (issue #338, ADR 0068).** Every builder wrote such an SE as `+inf` beside a finite `z`, warned only by numpy's `overflow encountered in cast`; now both `z` and `se` carry the plane's Missing Marker (a Ragged sequence does not retain the association), at every point a build or Reference Completion narrows SE, before the encoding is measured. The encoders raise rather than write `+inf`. A new required `analyses.tsv` column, `n_missing_se_out_of_range`, counts them per Analysis (a Hybrid's root counts both components; a release written before it reads as unknown, never 0). `0.2.0` still reads without a warning and completes in place; completion also masks a `0.2.0` source's own `+inf` cells, and the Observed-View Check accepts exactly that transition. The converter writes `0.2.1` and refuses a `0.1.0` source holding such an SE — rebuild it. Spec §6a, §7a, §12, §20, §21; `docs/store-format-compatibility.md` has the new row.

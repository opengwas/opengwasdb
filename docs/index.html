OpenGWASDB at full scale — OGS-00009

Every UK Biobank ukb-b GWAS in the OpenGWAS collection — all 2,024 traits, 9,847,701 variants, 19.9 billion associations — in a single Dense Store Release, with query timings and memory footprint measured through the public API.

  • 9.95×34.68 GB vs 345.01 GB of source VCF
  • 1.12 mstop hits for one trait
  • 7.93 msPheWAS across all 2,024 traits
  • ~157 MBRAM to open and query the store

This is the headline evidence for the project: a whole GWAS collection compressed an order of magnitude, queried in milliseconds, on memory a laptop has. Read the full report →

Rendered reports

  • OGS-00009 — Full-scale performance and memory footprint
    All 2,024 UK Biobank ukb-b GWAS (9,847,701 variants, 19.9 billion associations): every query-shape timing, per-shape peak memory, storage and build against the raw VCF collection (9.95× smaller), and an end-to-end MR IVW run as a correctness check.
  • ukb-b Dense Store — format 2.0 vs format 3.0
    Residual-coded standard errors measured against the float16 release on the same data (issue #148): storage reduction, build cost and per-query latency change for each encoding. Measured on the earlier 2,514-Analysis ukb-b store.
  • Hybrid Layout — Hybrid vs Dense-of-union (BMI · CAD · LDL)
    Three heterogeneous consortium GWAS built as a Hybrid store (Dense Component on the panel + Ragged Overflow for off-panel observed variants) and as a Dense-of-union store: storage split, per-query latency, imputed-only positive-control MR (LDL→CAD, BMI→CAD) vs observed, and a regional imputation plot.
  • Ancestry Assignment — Full ieu-a / ieu-b / bbj-a batch (815 GWAS, genome-wide)
    Every study in the ieu-a, ieu-b and bbj-a collections assigned an ancestry from its allele frequencies against a hg19 reference: 527 assigned with zero reported-vs-assigned misassignments, and the 288 Unassigned traced entirely to data quality (empty or mis-oriented AF), not admixture. Store routing then folds in a reported-ancestry fallback and a genome-wide coverage gate (≥500k variants, all autosomes) to leave 721 store-eligible studies (578 EUR, 137 EAS).
  • Ancestry Assignment — Reported population vs AF-recovered ancestry (ieu-a · bbj, chr1)
    Recovering each GWAS's ancestry from its summary-stat allele frequencies (NNLS mixture of the Privé 2022 reference, hg19→hg38 lifted) and the τ/δ/overlap admission gate (τ ≥ 0.5, δ ≥ 0.2, ≥ 5k sites), on chr1 of real ieu-a / Biobank-Japan studies: three declared-"Mixed" studies recovered as European, with East-Asian, African-American, and admixed labels landing on their matching super-population.
  • ukb-b Dense Store — Chunk-Shape Query Benchmark (1000×1000 vs 1000×128)
    Same genome-wide ukb-b data at two zarr chunk shapes: the narrower analysis chunk makes the per-analysis (bulk) read ~4× faster; with surgical point lookups (issue 052) scattered lookups are back at parity, leaving only a small per-variant PheWAS cost. Speedup table and log-scale bar chart.
  • OpenGWASDB vs besdq — Performance Comparison
    Storage and query performance comparison: chr1 × 100 UKB analyses, Dense observed-only store vs besdq baseline.
  • UKB chr1 Dense Store — Array Query API Benchmark
    Query latency and storage for sparse array return contract (chr1 × 100 analyses).
  • UKB chr1 Dense Store — 1000-Analysis Benchmark
    Large-scale companion to the 100-analysis run: same 762,080 variants, 10× the analyses. Storage, build time, and query-latency scaling (chr1 × 1000 analyses).
  • UKB chr1 Dense Store — Array Query API Benchmark (pre-fix baseline)
    Baseline timings before query optimization fixes.
  • UKB chr1 Dense Store — bcftools Build Time Benchmark
    Build time comparison: bcftools (subprocess) vs cyvcf2 VCF reader.
  • eQTLGen Ragged Store — Performance and Storage Benchmark
    Query latency and compression ratio for Ragged (CSR) layout with eQTLGen cis-eQTL source.
  • OpenGWASDB Dense Benchmark — EBI Full GWAS-SSF Inputs
    Dense benchmark using three full GWAS-SSF files (EBI format).

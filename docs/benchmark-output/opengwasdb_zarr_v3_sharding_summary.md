Every column returned identical results (sha256 per shape) on all 7 shapes and on the 2 Overflow shapes. **The before column is not paired with the Zarr 3 columns**: it was written at 04:06 UTC and they at 09:27 UTC.

The Overflow shapes ran under Zarr 2.18.7 at `745796c` (before) and Zarr 3.4.0 at `850b3c7` (this code), with every repetition gated at a 1-minute load below 3.

**Caveats.** The off-panel Overflow PheWAS on OGS-00011 is **1.28× the 2.18 time** on 0.2.0 (28.97 s against 22.64 s). It is the only measured shape at least a second slower than the status quo. The cost is this code's, not the format's: 0.2.0 is 1.03× this code on 0.1.0, with overlapping repetitions. Which part of the code causes it is unestablished. #252's A/B, with the reader held fixed, recorded the pre-#252 decode at 28.96 s and the windowed scan at 22.62 s (one run each), and an earlier version of that artifact had the opposite sign. ADR 0060's by-variant index removes the scan either way. Validation memory scales with the store (#254). The 0.2.0 conversions peaked at 45.45 GiB on OGS-00016 and 192.58 GiB on OGS-00011; the phase times attribute those peaks to validation, which is inferred, not sampled. Follow-ups: #252 step 1 (restore a Ragged baseline), step 2 (the scaling experiment) and step 5 (build ADR 0060's by-variant index); #257 (single-pass and two-pass Hybrid builds disagree on association-less off-reference variants); #258 (a `--variant-reference` that names some rsids leaves the rest blank).

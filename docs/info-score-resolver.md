# CORE INFO resolver diagnostics (stores #175)

`resolve-analyses` reads only the manifest-declared GWAS-SSF imputation-score column, kind and independent provider provenance. A familiar source header is not a declaration. An exact column mismatch or an Analysis with no usable declared scores is a controlled failure naming the Analysis. For a positive threshold in (0, 1], rows with unusable statuses or a usable score strictly below the threshold are removed **before** ancestry, SD, and build-routing evidence. Equality passes. Explicit zero (`disabled`), literal `NaN` (`unavailable`) and absent legacy (`legacy_absent`) retain all canonical rows; their `info_score_state` and fingerprints differ.

Per-Analysis JSON `diagnostics` API (all row counts are pre-deduplication):

- `canonical_rows_observed` (`rows_read` alias) counts canonical-identity rows yielded by the reader over the *physical scan prefix*, not raw source lines. Unnormalisable identities dropped in the reader are not observable here. `stop_reason` is `eof`, `row_limit`, or `ancestry_site_limit`; a prefix is **not** a whole-file count.
- `canonical_rows_retained` counts rows after INFO filtering. `info_rows_below_threshold` counts usable scores below a positive threshold. `info_rows_missing`, `info_rows_malformed`, `info_rows_nonfinite`, `info_rows_out_of_range`, `info_rows_usable` are dispositions among observed rows, including at threshold zero. Under positive filtering: observed = retained + below threshold + the four unusable dispositions. Undeclared legacy/NaN sources have zero declared-score dispositions.
- `build_eligible_rows` counts retained rows with a finite beta and strictly positive finite SE yielding a finite z. With `--variant-reference`, `build_eligible_rows_on_variant_reference` and `build_eligible_rows_off_variant_reference` partition this eligible count; without it both are `null`. These counts are **rows**, not stored Dense cells. Duplicate variants, allele routing and builder decisions can reduce the final cell count; no parity to actual Dense cells is implied by a sampled prefix.
- `ancestry_reference_rows_matched` now counts retained rows on the ancestry reference in the ancestry accumulation prefix. Legacy `variant_reference_rows_matched` remains **pre-INFO** canonical rows on the variant reference over the physical scan, for backward compatibility. It must **not** be used as a post-INFO build denominator.
